# FPGA 动漫音乐播放器与电子时钟闹铃系统实现流程详解

这份文档的目标不是写实验报告，而是把这个工程从零讲清楚：它为什么要分成这些模块，每个模块输入输出是什么意思，代码每一段在干什么，最后这些模块又是怎样连成一个完整系统的。

项目目录：

```text
anime_music_player/
  anime_music_player.srcs/
    sources_1/new/
      anime_music_player_top.sv
      key_debounce.sv
      note_scheduler.sv
      pitch_decoder.sv
      pwm_gen.sv
      clock_core.sv
      hex8_scan.sv
      hc595_driver.sv
      song_rom.sv
    constrs_1/new/
      anime_music_player.xdc
```

目前工程里没有单独写 testbench 仿真文件，主要验证方式是：综合、实现、生成 bitstream，然后下载到板子上看蜂鸣器、LED 和数码管表现。

## 1. 先建立整体认识

这个工程做了两件大事：

1. 音乐播放器：按键控制播放/暂停、切歌、加速、减速；蜂鸣器播放歌曲；LED 和数码管显示状态。
2. 电子时钟闹铃：数码管显示 `HH-MM-SS`；可以设置时间、暂停计时、设置闹铃；闹铃时间到了以后自动播放歌曲。

它用到的硬件资源：

| 硬件 | 在代码里的端口 | 用途 |
|---|---|---|
| 50 MHz 时钟 | `clk` | 所有时序逻辑的节拍来源 |
| 复位键 | `reset_n` | 低电平复位 |
| 4 个按键 | `key0` 到 `key3` | 控制播放、切歌、速度、时间设置 |
| 拨码开关 | `sw_vol`, `sw_mode`, `sw_alarm_*` | 选择音量、模式、闹铃参数 |
| 蜂鸣器 | `beep` | 输出 PWM 方波发声 |
| LED | `led[7:0]` | 显示状态 |
| 8 位数码管 | `seg_dio`, `seg_sclk`, `seg_rclk` | 通过 74HC595 驱动显示数据 |

最重要的信号流可以这样理解：

```text
按键/开关
   |
   v
顶层控制 anime_music_player_top
   |
   +--> 音乐播放链路：note_scheduler -> pitch_decoder -> pwm_gen -> beep
   |
   +--> 时钟闹铃链路：clock_core -> 闹铃触发 -> 强制音乐播放
   |
   +--> 显示链路：disp_data -> hex8_scan -> hc595_driver -> 数码管
   |
   +--> LED 状态显示
```

## 2. 需要先懂的 HDL 基础

### 2.1 `wire` 和 `reg` 是什么

在这个工程里，你会看到：

```verilog
wire key0_pulse;
reg  play_en;
```

简单理解：

- `wire` 像一根线，它通常由 `assign` 或模块输出驱动。
- `reg` 像一个可以保存值的变量，通常在 `always` 块里赋值。

注意：`reg` 不一定真的综合成寄存器。只有在时钟触发的 `always @(posedge clk ...)` 里保存状态时，才通常会变成触发器。

### 2.2 组合逻辑和时序逻辑

组合逻辑没有记忆，输入变了，输出马上按逻辑变化：

```verilog
always @(*) begin
    case (sw_vol)
        2'b00: counter_ccr = counter_arr >> 3;
        2'b01: counter_ccr = counter_arr >> 2;
        2'b10: counter_ccr = counter_arr >> 1;
        2'b11: counter_ccr = counter_arr - (counter_arr >> 2);
    endcase
end
```

时序逻辑有时钟，只有时钟上升沿到来时才更新：

```verilog
always @(posedge clk or negedge reset_n) begin
    if (!reset_n)
        play_en <= 1'b0;
    else if (key0_pulse)
        play_en <= ~play_en;
end
```

本工程绝大部分状态，比如播放状态、歌曲编号、时间计数、PWM 计数器，都是时序逻辑。

### 2.3 为什么时序逻辑里用 `<=`

你会看到时序逻辑里基本都是：

```verilog
play_en <= ~play_en;
```

这是非阻塞赋值，适合描述触发器。它的含义是：这个时钟沿先看右边旧值，等这个时钟沿结束后一起更新左边。

组合逻辑里通常用 `=`：

```verilog
counter_ccr = counter_arr >> 1;
```

## 3. 顶层模块：`anime_music_player_top.sv`

顶层模块是整个系统的“总指挥”。它不应该把所有功能都写死在一个文件里，而是负责：

1. 接收板子上的输入信号；
2. 例化其他子模块；
3. 决定音乐模式和时钟模式下哪些信号生效；
4. 把最终输出送到蜂鸣器、LED 和数码管。

### 3.1 顶层端口

源码开头：

```verilog
module anime_music_player_top (
    input  wire       clk,
    input  wire       reset_n,

    input  wire       key0,
    input  wire       key1,
    input  wire       key2,
    input  wire       key3,

    input  wire [1:0] sw_vol,
    input  wire       sw_mode,
    input  wire [1:0] sw_alarm_song,
    input  wire       sw_alarm_en,
    input  wire       sw_alarm_set,

    output wire       beep,
    output wire [7:0] led,

    output wire       seg_dio,
    output wire       seg_sclk,
    output wire       seg_rclk
);
```

解释：

- `clk` 是 50 MHz 时钟，所有模块都靠它运行。
- `reset_n` 是低有效复位，`n` 表示 negative active，也就是按下时为 0。
- `key0` 到 `key3` 是四个独立按键。
- `sw_vol[1:0]` 是两位音量选择，有 `00/01/10/11` 四档。
- `sw_mode` 是模式切换，`0` 是音乐模式，`1` 是时钟模式。
- `sw_alarm_song` 选择闹铃播放哪首歌。
- `sw_alarm_en` 是闹铃使能。
- `sw_alarm_set` 是闹铃设置模式。
- `beep` 接蜂鸣器。
- `led[7:0]` 接 8 个 LED。
- `seg_dio/seg_sclk/seg_rclk` 是给 74HC595 的三根线，用来驱动数码管。

### 3.2 四个按键都先消抖

机械按键会抖动，所以不能直接用 `key0` 控制播放。顶层先例化四个 `key_debounce`：

```verilog
wire key0_pulse;
wire key1_pulse;
wire key2_pulse;
wire key3_pulse;

key_debounce u_key0 (
    .clk       (clk),
    .reset_n   (reset_n),
    .key_in    (key0),
    .key_pulse (key0_pulse)
);
```

四个按键结构完全相同，只是输入不同、输出不同。

你可以把 `key0_pulse` 理解为：“S0 被稳定按下一次后，产生一个时钟周期的脉冲”。这样后面就可以写：

```verilog
if (key0_pulse)
    play_en <= ~play_en;
```

这表示每按一次，播放状态翻转一次。

### 3.3 为什么拨码开关也要同步

代码：

```verilog
reg  sw_mode_r0;
reg  sw_mode_r1;
wire clock_mode;

always @(posedge clk or negedge reset_n) begin
    if (!reset_n) begin
        sw_mode_r0 <= 1'b0;
        sw_mode_r1 <= 1'b0;
    end else begin
        sw_mode_r0 <= sw_mode;
        sw_mode_r1 <= sw_mode_r0;
    end
end

assign clock_mode = sw_mode_r1;
```

拨码开关是外部输入，不一定刚好在时钟边沿附近稳定。直接拿它控制时序逻辑，可能产生亚稳态。这里用了两级寄存器：

```text
外部 sw_mode -> sw_mode_r0 -> sw_mode_r1 -> clock_mode
```

这叫两级同步器。它不能百分百消灭亚稳态，但可以大幅降低风险。

同理，闹铃相关开关也做了同步：

```verilog
reg [1:0] sw_alarm_song_r0, sw_alarm_song_r1;
reg       sw_alarm_en_r0,   sw_alarm_en_r1;
reg       sw_alarm_set_r0,  sw_alarm_set_r1;
```

### 3.4 检测进入时钟模式的瞬间

代码：

```verilog
reg  clock_mode_d;
wire clock_mode_rise;

always @(posedge clk or negedge reset_n) begin
    if (!reset_n)
        clock_mode_d <= 1'b0;
    else
        clock_mode_d <= clock_mode;
end

assign clock_mode_rise = clock_mode && !clock_mode_d;
```

`clock_mode_d` 保存上一拍的 `clock_mode`。

如果：

- 当前 `clock_mode = 1`
- 上一拍 `clock_mode_d = 0`

说明刚刚从音乐模式切到时钟模式，于是 `clock_mode_rise = 1`，只持续一个时钟周期。

这个信号后面用来立刻关闭普通音乐播放：

```verilog
else if (clock_mode_rise) begin
    play_en <= 1'b0;
end
```

### 3.5 音乐播放状态寄存器

代码：

```verilog
reg       play_en;
reg [1:0] song_id;
reg [1:0] speed_level;
```

三个状态：

- `play_en`：是否播放。
- `song_id`：当前歌曲编号，工程中用了 0、1、2 三首。
- `speed_level`：速度档位，0 慢，1 正常，2 快。

核心逻辑：

```verilog
always @(posedge clk or negedge reset_n) begin
    if (!reset_n) begin
        play_en     <= 1'b0;
        song_id     <= 2'd0;
        speed_level <= 2'd1;
    end else if (clock_mode_rise) begin
        play_en <= 1'b0;
    end else if (!clock_mode) begin
        if (key0_pulse)
            play_en <= ~play_en;

        if (key1_pulse) begin
            if (song_id == 2'd2)
                song_id <= 2'd0;
            else
                song_id <= song_id + 1'b1;
        end

        if (key2_pulse) begin
            if (speed_level < 2'd2)
                speed_level <= speed_level + 1'b1;
        end

        if (key3_pulse) begin
            if (speed_level > 2'd0)
                speed_level <= speed_level - 1'b1;
        end
    end
end
```

逐句解释：

- 复位时：不播放，歌曲为第 0 首，速度为正常档。
- 如果刚进入时钟模式：关闭普通音乐。
- 如果当前在音乐模式：
  - S0：播放/暂停。
  - S1：切到下一首，2 后回到 0。
  - S2：速度加一，最大到 2。
  - S3：速度减一，最小到 0。

注意这里的 `else if (!clock_mode)` 很关键：只有音乐模式下，这四个按键才控制音乐。时钟模式下，这四个按键会交给 `clock_core` 使用。

### 3.6 闹铃响起时如何强制播放歌曲

闹铃功能在 `clock_core` 里判断，但真正发声还是复用音乐播放链路。顶层定义：

```verilog
wire [1:0] effective_song_id;
wire       effective_play_en;
wire [1:0] effective_speed_level;

assign effective_song_id     = (clock_mode && clock_alarm_active) ? alarm_song_id : song_id;
assign effective_play_en     = (clock_mode && clock_alarm_active) ? 1'b1          : ((!clock_mode) && play_en);
assign effective_speed_level = (clock_mode && clock_alarm_active) ? 2'd1          : speed_level;
```

这里的 `effective_` 意思是“最终真正送去播放模块的值”。

分两种情况：

1. 时钟模式并且闹铃正在响：
   - 歌曲编号用 `alarm_song_id`
   - 强制播放 `1'b1`
   - 速度强制正常档 `2'd1`
2. 其他情况：
   - 音乐模式用普通音乐状态
   - 时钟模式没有闹铃时不播放

这个设计很聪明：闹铃不用重新写一套蜂鸣器模块，而是复用音乐播放器。

### 3.7 音乐播放链路如何串起来

顶层例化：

```verilog
note_scheduler u_note_scheduler (
    .clk           (clk),
    .reset_n       (reset_n),
    .play_en       (effective_play_en),
    .song_id       (effective_song_id),
    .speed_level   (effective_speed_level),
    .restart_pulse (alarm_start_pulse),
    .note_word     (note_word),
    .note_change   (note_change)
);

pitch_decoder u_pitch_decoder (
    .note_word   (note_word),
    .counter_arr (counter_arr)
);

pwm_gen u_pwm_gen (
    .clk         (clk),
    .reset_n     (reset_n),
    .pwm_en      (effective_play_en && (counter_arr != 32'd0)),
    .counter_arr (counter_arr),
    .counter_ccr (counter_ccr),
    .pwm_out     (beep)
);
```

信号流：

```text
song_id + speed_level + play_en
      |
      v
note_scheduler
      |
      v
note_word，也就是“当前音符”
      |
      v
pitch_decoder
      |
      v
counter_arr，也就是 PWM 周期
      |
      v
pwm_gen
      |
      v
beep 蜂鸣器
```

### 3.8 音量如何控制

代码：

```verilog
always @(*) begin
    case (sw_vol)
        2'b00: counter_ccr = counter_arr >> 3;
        2'b01: counter_ccr = counter_arr >> 2;
        2'b10: counter_ccr = counter_arr >> 1;
        2'b11: counter_ccr = counter_arr - (counter_arr >> 2);
        default: counter_ccr = counter_arr >> 1;
    endcase
end
```

`counter_arr` 是 PWM 一个周期的长度。`counter_ccr` 是高电平持续多久。

例如：

- `counter_arr >> 3` 等于周期的 1/8，占空比较小。
- `counter_arr >> 1` 等于周期的 1/2，占空比 50%。
- `counter_arr - (counter_arr >> 2)` 等于周期的 3/4，占空比较大。

蜂鸣器听起来的响度会随占空比变化。

### 3.9 节奏 LED

代码：

```verilog
reg [2:0] rhythm_led;

always @(posedge clk or negedge reset_n) begin
    if (!reset_n) begin
        rhythm_led <= 3'b001;
    end else if (note_change) begin
        rhythm_led <= {rhythm_led[1:0], rhythm_led[2]};
    end
end
```

`note_change` 每切换一个音符就产生一次。于是 LED 会循环：

```text
001 -> 010 -> 100 -> 001 -> ...
```

这就是节奏灯效果。

### 3.10 数码管显示数据如何组织

音乐模式显示：

```verilog
assign disp_song   = {2'b00, song_id} + 4'd1;
assign disp_play   = play_en ? 4'd1 : 4'd0;
assign disp_speed  = {2'b00, speed_level};
assign disp_octave = note_word[15:12];
assign disp_note   = note_word[11:8];
assign disp_vol    = {2'b00, sw_vol};

assign music_disp_data = {
    disp_song,
    4'hF,
    disp_play,
    4'hF,
    disp_speed,
    disp_vol,
    disp_octave,
    disp_note
};
```

`disp_data` 是 32 位，分成 8 个 4 位：

```text
最高位                                   最低位
[31:28] [27:24] [23:20] [19:16] [15:12] [11:8] [7:4] [3:0]
 song     blank    play    blank   speed   vol   octave note
```

其中 `4'hF` 在 `hex8_scan` 中显示为空白。

时钟模式显示由 `clock_core` 给出：

```verilog
assign disp_data = clock_mode ? clock_disp_data : music_disp_data;
```

这就是显示复用：一个数码管显示模块，根据模式显示不同内容。

### 3.11 LED 显示如何组织

代码：

```verilog
assign led = clock_mode ?
    {clock_blink, clock_alarm_active, 3'b000, clock_set_field, clock_running} :
    {rhythm_led, speed_level, song_id, play_en};
```

音乐模式：

```text
led[7:5] = rhythm_led
led[4:3] = speed_level
led[2:1] = song_id
led[0]   = play_en
```

时钟模式：

```text
led[7]   = clock_blink
led[6]   = clock_alarm_active
led[5:3] = 000
led[2:1] = clock_set_field
led[0]   = clock_running
```

### 3.12 数码管驱动链路

顶层最后：

```verilog
hex8_scan u_hex8_scan (
    .clk       (clk),
    .reset_n   (reset_n),
    .en        (1'b1),
    .disp_data (disp_data),
    .sel       (seg_sel),
    .seg       (seg_seg)
);

hc595_driver u_hc595_driver (
    .clk     (clk),
    .reset_n (reset_n),
    .data    ({1'b1, seg_seg, seg_sel}),
    .s_en    (1'b1),
    .ds      (seg_dio),
    .sh_cp   (seg_sclk),
    .st_cp   (seg_rclk)
);
```

含义：

1. `hex8_scan` 把 32 位显示数据变成“当前选哪一位”和“当前显示什么段码”。
2. `hc595_driver` 把这些并行数据串行送给 74HC595。

## 4. 按键消抖模块：`key_debounce.sv`

这个模块很适合初学者认真学，因为它体现了两个很重要的概念：

1. 异步输入同步。
2. 机械按键消抖。

### 4.1 模块接口

```verilog
module key_debounce #(
    parameter CNT_MAX = 20'd1_000_000
)(
    input  wire clk,
    input  wire reset_n,
    input  wire key_in,
    output reg  key_pulse
);
```

解释：

- `CNT_MAX` 是参数。默认 1,000,000。
- 50 MHz 时钟周期是 20 ns。
- 1,000,000 个周期就是 20 ms。

也就是说：按键电平变化后，要稳定 20 ms 才承认这次按键有效。

### 4.2 两级同步

```verilog
reg key_sync0;
reg key_sync1;

always @(posedge clk or negedge reset_n) begin
    if (!reset_n) begin
        key_sync0 <= 1'b1;
        key_sync1 <= 1'b1;
    end else begin
        key_sync0 <= key_in;
        key_sync1 <= key_sync0;
    end
end
```

按键没按时通常是高电平，所以复位设为 `1'b1`。

同步链路：

```text
key_in -> key_sync0 -> key_sync1
```

后续逻辑不用原始 `key_in`，而用同步后的 `key_sync1`。

### 4.3 稳定状态和计数器

```verilog
reg key_state;
reg [19:0] cnt;
```

- `key_state`：当前认为的稳定按键状态。
- `cnt`：输入电平和稳定状态不一致时，开始计数。

### 4.4 消抖核心逻辑

```verilog
always @(posedge clk or negedge reset_n) begin
    if (!reset_n) begin
        key_state <= 1'b1;
        key_pulse <= 1'b0;
        cnt <= 20'd0;
    end else begin
        key_pulse <= 1'b0;

        if (key_sync1 == key_state) begin
            cnt <= 20'd0;
        end else begin
            if (cnt == CNT_MAX - 1'b1) begin
                key_state <= key_sync1;
                cnt <= 20'd0;

                if (key_sync1 == 1'b0)
                    key_pulse <= 1'b1;
            end else begin
                cnt <= cnt + 1'b1;
            end
        end
    end
end
```

逐步理解：

1. 每个时钟周期先默认 `key_pulse <= 0`。  
   这样如果后面没有特殊情况，输出就是 0。

2. 如果 `key_sync1 == key_state`：  
   说明输入和当前稳定状态一致，没有变化，计数器清零。

3. 如果 `key_sync1 != key_state`：  
   说明输入状态可能变化了，也可能只是抖动，开始计数。

4. 如果计数到 `CNT_MAX - 1`：  
   说明这个新状态已经稳定了约 20 ms，于是接受它：

   ```verilog
   key_state <= key_sync1;
   ```

5. 如果新稳定状态是 `0`，说明按键稳定按下，于是输出一个脉冲：

   ```verilog
   if (key_sync1 == 1'b0)
       key_pulse <= 1'b1;
   ```

为什么只在按下时输出，不在松开时输出？因为这个工程只需要“按下一次触发一次”，不需要松开事件。

## 5. 音符调度模块：`note_scheduler.sv`

这个模块回答一个问题：现在应该播放哪一个音符？

它不负责产生声音，只负责按时间顺序取出音符。

### 5.1 模块接口

```verilog
module note_scheduler (
    input  wire        clk,
    input  wire        reset_n,
    input  wire        play_en,
    input  wire [1:0]  song_id,
    input  wire [1:0]  speed_level,
    input  wire        restart_pulse,

    output reg  [15:0] note_word,
    output reg         note_change
);
```

输入：

- `play_en`：是否播放。
- `song_id`：播放哪首歌。
- `speed_level`：播放速度。
- `restart_pulse`：重头播放的脉冲。闹铃刚开始响时用它回到歌曲开头。

输出：

- `note_word`：当前音符编码。
- `note_change`：音符切换脉冲，给节奏 LED 用。

### 5.2 歌曲地址范围

```verilog
reg [7:0] addr;
reg [7:0] start_addr;
reg [7:0] end_addr;
```

歌曲存在 ROM 里，每个地址是一条音符。

```verilog
always @(*) begin
    case (song_id)
        2'd0: begin
            start_addr = 8'd0;
            end_addr   = 8'd38;
        end

        2'd1: begin
            start_addr = 8'd48;
            end_addr   = 8'd90;
        end

        2'd2: begin
            start_addr = 8'd112;
            end_addr   = 8'd151;
        end

        default: begin
            start_addr = 8'd0;
            end_addr   = 8'd38;
        end
    endcase
end
```

意思：

- 第 0 首歌存在地址 0 到 38。
- 第 1 首歌存在地址 48 到 90。
- 第 2 首歌存在地址 112 到 151。

中间留空是为了以后扩展或者整理 ROM。

### 5.3 ROM IP 读取

```verilog
wire [15:0] rom_note_word;

anime_song_rom u_anime_song_rom (
    .clka  (clk),
    .addra (addr),
    .douta (rom_note_word)
);
```

这里例化的是 Vivado 生成的 ROM IP，名字叫 `anime_song_rom`。

它的工作方式：

```text
输入 addr
经过 ROM 读取
输出 rom_note_word
```

然后：

```verilog
always @(posedge clk or negedge reset_n) begin
    if (!reset_n)
        note_word <= 16'd0;
    else
        note_word <= rom_note_word;
end
```

这表示每个时钟把 ROM 输出寄存到 `note_word`。

### 5.4 速度档位

```verilog
reg [31:0] base_ticks;

always @(*) begin
    case (speed_level)
        2'd0: base_ticks = 32'd8_000_000;
        2'd1: base_ticks = 32'd6_250_000;
        2'd2: base_ticks = 32'd4_500_000;
        default: base_ticks = 32'd6_250_000;
    endcase
end
```

50 MHz 时钟下：

- 8,000,000 个周期约 160 ms。
- 6,250,000 个周期约 125 ms。
- 4,500,000 个周期约 90 ms。

所以数值越小，换音符越快。

### 5.5 音长字段

```verilog
wire [2:0] duration_raw;
wire [2:0] duration_unit;

assign duration_raw  = note_word[5:3];
assign duration_unit = (duration_raw == 3'd0) ? 3'd1 : duration_raw;

wire [34:0] note_ticks;
assign note_ticks = base_ticks * duration_unit;
```

音符编码里 `[5:3]` 是音长。

如果音长写成 0，就当成 1，避免 `note_ticks = 0`。

最终音符持续时间：

```text
note_ticks = 基础节拍 * 音长单位
```

例如正常速度 `base_ticks = 6_250_000`，音长 `dur=2`，就播放 `12_500_000` 个时钟周期。

### 5.6 地址推进逻辑

核心代码：

```verilog
always @(posedge clk or negedge reset_n) begin
    if (!reset_n) begin
        addr         <= 8'd0;
        tick_cnt     <= 35'd0;
        last_song_id <= 2'd0;
        note_change  <= 1'b1;
    end else begin
        note_change <= 1'b0;

        if (restart_pulse) begin
            addr         <= start_addr;
            tick_cnt     <= 35'd0;
            last_song_id <= song_id;
            note_change  <= 1'b1;
        end else if (song_id != last_song_id) begin
            addr         <= start_addr;
            tick_cnt     <= 35'd0;
            last_song_id <= song_id;
            note_change  <= 1'b1;
        end else if (play_en) begin
            if (tick_cnt >= note_ticks - 1'b1) begin
                tick_cnt <= 35'd0;
                note_change <= 1'b1;

                if (addr >= end_addr)
                    addr <= start_addr;
                else
                    addr <= addr + 1'b1;
            end else begin
                tick_cnt <= tick_cnt + 1'b1;
            end
        end
    end
end
```

优先级从高到低：

1. 复位：回到地址 0。
2. `restart_pulse`：回到当前歌曲开头。闹铃开始响时用。
3. `song_id` 改变：切歌，回到新歌曲开头。
4. 正在播放：计时，时间到了就切下一个音符。

`note_change` 每次音符变化时置 1，一个时钟周期后默认回 0。

## 6. 音高译码模块：`pitch_decoder.sv`

这个模块回答一个问题：当前音符应该对应多高的频率？

### 6.1 模块接口

```verilog
module pitch_decoder (
    input  wire [15:0] note_word,
    output reg  [31:0] counter_arr
);
```

输入是音符编码 `note_word`。输出是 PWM 周期 `counter_arr`。

### 6.2 从音符里取出音区和音名

```verilog
wire [3:0] octave;
wire [3:0] note;

assign octave = note_word[15:12];
assign note   = note_word[11:8];
```

编码格式：

```text
note_word[15:12] = octave 音区
note_word[11:8]  = note 音名
```

### 6.3 查表得到 PWM 周期

代码结构：

```verilog
always @(*) begin
    counter_arr = 32'd0;

    case (octave)
        4'd0: begin
            case (note)
                4'd1: counter_arr = 32'd382225;
                ...
                default: counter_arr = 32'd0;
            endcase
        end

        4'd1: begin
            case (note)
                4'd1: counter_arr = 32'd191113;
                ...
            endcase
        end

        4'd2: begin
            case (note)
                4'd1: counter_arr = 32'd95557;
                ...
            endcase
        end

        default: begin
            counter_arr = 32'd0;
        end
    endcase
end
```

这是一个组合逻辑查表。

`counter_arr` 越小，PWM 频率越高，听起来音越高。

大致关系：

```text
输出频率 = 50_000_000 / counter_arr
```

例如中音 Do：

```text
counter_arr = 191113
频率约 = 50,000,000 / 191113 = 261.6 Hz
```

这就是 C4 附近。

如果 `note` 不在 1 到 7，就输出 0，表示休止或无效音符。

## 7. PWM 发生器：`pwm_gen.sv`

这个模块真正产生蜂鸣器的方波。

### 7.1 模块接口

```verilog
module pwm_gen (
    input  wire        clk,
    input  wire        reset_n,
    input  wire        pwm_en,
    input  wire [31:0] counter_arr,
    input  wire [31:0] counter_ccr,
    output reg         pwm_out
);
```

解释：

- `pwm_en`：是否输出 PWM。
- `counter_arr`：周期长度。
- `counter_ccr`：高电平持续长度。
- `pwm_out`：输出到蜂鸣器。

### 7.2 内部计数器

```verilog
reg [31:0] counter;
```

它从 0 一直数到 `counter_arr`，然后回到 0。

### 7.3 核心逻辑

```verilog
always @(posedge clk or negedge reset_n) begin
    if (!reset_n) begin
        counter <= 32'd0;
        pwm_out <= 1'b0;
    end else begin
        if (!pwm_en || counter_arr == 32'd0) begin
            counter <= 32'd0;
            pwm_out <= 1'b0;
        end else begin
            if (counter >= counter_arr)
                counter <= 32'd0;
            else
                counter <= counter + 1'b1;

            if (counter < counter_ccr)
                pwm_out <= 1'b1;
            else
                pwm_out <= 1'b0;
        end
    end
end
```

分情况：

1. 复位：计数器清零，输出低。
2. 没有使能或周期为 0：不发声。
3. 正常输出：
   - `counter` 到 `counter_arr` 后回 0。
   - 当 `counter < counter_ccr` 时输出 1。
   - 否则输出 0。

举例：

```text
counter_arr = 100
counter_ccr = 50

counter: 0 1 2 ... 49 50 51 ... 100
pwm_out: 1 1 1 ... 1  0  0  ... 0
```

这就是 50% 占空比方波。

## 8. 电子时钟与闹铃核心：`clock_core.sv`

这个模块是工程里逻辑最复杂的部分。它负责：

1. 产生 1 秒节拍。
2. 保存当前时间。
3. 支持按键修改时间。
4. 保存闹铃时间。
5. 判断闹铃是否触发。
6. 输出数码管显示数据。

### 8.1 模块接口

```verilog
module clock_core (
    input  wire        clk,
    input  wire        reset_n,

    input  wire        key_sel_pulse,
    input  wire        key_inc_pulse,
    input  wire        key_dec_pulse,
    input  wire        key_pause_pulse,

    input  wire        alarm_set_mode,
    input  wire        alarm_enable,
    input  wire [1:0]  alarm_song_sel,

    output wire [31:0] disp_data,
    output reg  [1:0]  set_field,
    output reg         clock_running,
    output reg         blink_1hz,
    output reg         alarm_active
);
```

按键含义：

- `key_sel_pulse`：选择当前要修改的字段。
- `key_inc_pulse`：当前字段加一。
- `key_dec_pulse`：当前字段减一。
- `key_pause_pulse`：停止闹铃，或暂停/继续计时。

闹铃输入：

- `alarm_set_mode = 0`：设置当前时间。
- `alarm_set_mode = 1`：设置闹铃时间。
- `alarm_enable`：闹铃开关。
- `alarm_song_sel`：选择闹铃歌号显示。

输出：

- `disp_data`：给数码管显示的 32 位数据。
- `set_field`：当前正在编辑哪个字段。
- `clock_running`：时钟是否正在走。
- `blink_1hz`：1 Hz 闪烁 LED。
- `alarm_active`：闹铃是否正在响。

### 8.2 1 秒分频

```verilog
localparam integer CLK_FREQ   = 50_000_000;

reg [25:0] div_cnt;
wire tick_1s;
assign tick_1s = (div_cnt == CLK_FREQ - 1);
```

50 MHz 意味着 1 秒有 50,000,000 个时钟周期。

`div_cnt` 从 0 数到 49,999,999，刚数到最后一个时：

```verilog
tick_1s = 1
```

持续一个时钟周期。

分频计数：

```verilog
always @(posedge clk or negedge reset_n) begin
    if (!reset_n)
        div_cnt <= 26'd0;
    else if (tick_1s)
        div_cnt <= 26'd0;
    else
        div_cnt <= div_cnt + 1'b1;
end
```

这就是 1 秒节拍来源。

### 8.3 BCD 时间存储

代码：

```verilog
reg [3:0] hour_t, hour_o;
reg [3:0] min_t,  min_o;
reg [3:0] sec_t,  sec_o;
```

这里不用二进制直接存小时分钟秒，而是用 BCD 分开存十位和个位。

例如时间 `23:59:08`：

```text
hour_t = 2
hour_o = 3
min_t  = 5
min_o  = 9
sec_t  = 0
sec_o  = 8
```

这样做的好处是数码管显示很方便，因为每个数字刚好是 4 位。

闹铃时间也类似：

```verilog
reg [3:0] alm_hour_t, alm_hour_o;
reg [3:0] alm_min_t,  alm_min_o;
```

闹铃只设置小时和分钟，不设置秒。

### 8.4 闹铃触发条件

```verilog
assign alarm_trigger = alarm_enable && !alarm_set_mode &&
                       (hour_t == alm_hour_t) && (hour_o == alm_hour_o) &&
                       (min_t  == alm_min_t)  && (min_o  == alm_min_o)  &&
                       (sec_t  == 4'd0)        && (sec_o  == 4'd0);
```

全部条件都满足才触发：

- 闹铃开关打开。
- 当前不在闹铃设置模式。
- 当前小时等于闹铃小时。
- 当前分钟等于闹铃分钟。
- 秒等于 00。

所以闹铃在某一分钟开始的那一刻触发。

### 8.5 复位初始值

```verilog
if (!reset_n) begin
    hour_t              <= 4'd0;
    hour_o              <= 4'd0;
    min_t               <= 4'd0;
    min_o               <= 4'd0;
    sec_t               <= 4'd0;
    sec_o               <= 4'd0;
    alm_hour_t          <= 4'd0;
    alm_hour_o          <= 4'd0;
    alm_min_t           <= 4'd0;
    alm_min_o           <= 4'd1;
    set_field           <= 2'd0;
    clock_running       <= 1'b1;
    blink_1hz           <= 1'b0;
    alarm_active        <= 1'b0;
    alarm_ring_sec      <= 4'd0;
    prev_alarm_set_mode <= 1'b0;
end
```

复位后：

- 当前时间：00:00:00。
- 默认闹铃：00:01。
- 时钟开始运行。
- 闹铃未响。

### 8.6 闹铃响铃管理

```verilog
if (!alarm_enable) begin
    alarm_active   <= 1'b0;
    alarm_ring_sec <= 4'd0;
end
```

如果闹铃开关关掉，立即停止。

自动停止：

```verilog
if (alarm_active && tick_1s) begin
    if (alarm_ring_sec >= ALARM_SECS - 1) begin
        alarm_active   <= 1'b0;
        alarm_ring_sec <= 4'd0;
    end else begin
        alarm_ring_sec <= alarm_ring_sec + 1'b1;
    end
end
```

`ALARM_SECS = 10`，所以响 10 秒后自动停止。

触发：

```verilog
if (alarm_trigger && !alarm_active) begin
    alarm_active   <= 1'b1;
    alarm_ring_sec <= 4'd0;
end
```

如果时间到了且当前没在响，就开始响。

按 S3 停止或暂停：

```verilog
if (key_pause_pulse) begin
    if (alarm_active)
        alarm_active <= 1'b0;
    else
        clock_running <= ~clock_running;
end
```

如果闹铃正在响，S3 优先停止闹铃；否则 S3 切换时钟运行/暂停。

### 8.7 选择正在编辑的字段

```verilog
if (key_sel_pulse) begin
    if (!alarm_set_mode) begin
        if (set_field == 2'd2) set_field <= 2'd0;
        else                   set_field <= set_field + 1'b1;
    end else begin
        set_field <= set_field[0] ? 2'd0 : 2'd1;
    end
end
```

如果设置当前时间：

```text
set_field = 0 -> 小时
set_field = 1 -> 分钟
set_field = 2 -> 秒
```

每按一次 S0，就循环到下一项。

如果设置闹铃：

```text
set_field = 0 -> 闹铃小时
set_field = 1 -> 闹铃分钟
```

因为闹铃没有秒，所以只在 0 和 1 之间切换。

### 8.8 自动走时

这段代码很长，本质就是 BCD 进位：

```verilog
if (clock_running && tick_1s) begin
    if (sec_o == 4'd9) begin
        sec_o <= 4'd0;
        if (sec_t == 4'd5) begin
            sec_t <= 4'd0;
            ...
        end else begin
            sec_t <= sec_t + 1'b1;
        end
    end else begin
        sec_o <= sec_o + 1'b1;
    end
end
```

规则：

- 秒个位 0 到 9。
- 秒十位 0 到 5。
- 分个位 0 到 9。
- 分十位 0 到 5。
- 小时从 00 到 23。
- 23:59:59 后回到 00:00:00。

这是数字钟最核心的计数逻辑。

### 8.9 修改当前时间

当前时间设置模式下：

```verilog
if (!alarm_set_mode) begin
    if (key_inc_pulse) begin
        case (set_field)
            2'd0: begin  // hour ++
                ...
            end
            2'd1: begin  // minute ++
                ...
            end
            2'd2: begin  // second ++
                ...
            end
        endcase
    end else if (key_dec_pulse) begin
        case (set_field)
            2'd0: begin  // hour --
                ...
            end
            2'd1: begin  // minute --
                ...
            end
            2'd2: begin  // second --
                ...
            end
        endcase
    end
end
```

加一和减一都要考虑边界：

- 小时加到 23 后再加变 00。
- 小时从 00 再减变 23。
- 分钟、秒钟从 59 后回 00，从 00 减回 59。

### 8.10 修改闹铃时间

闹铃设置模式下：

```verilog
else begin
    if (key_inc_pulse) begin
        if (set_field == 2'd0) begin
            // alarm hour ++
        end else begin
            // alarm minute ++
        end
    end else if (key_dec_pulse) begin
        if (set_field == 2'd0) begin
            // alarm hour --
        end else begin
            // alarm minute --
        end
    end
end
```

逻辑和当前时间设置类似，只是没有秒。

### 8.11 时钟显示数据

```verilog
assign disp_data = alarm_set_mode ?
    {4'hA, song_disp, 4'hE, alm_hour_t, alm_hour_o, 4'hE, alm_min_t, alm_min_o} :
    {hour_t, hour_o, 4'hE, min_t, min_o, 4'hE, sec_t, sec_o};
```

普通时钟显示：

```text
HH-MM-SS
```

例如 `12-34-56`：

```text
{1,2,E,3,4,E,5,6}
```

闹铃设置显示：

```text
A#-HH-MM
```

其中 `A` 表示 Alarm，`#` 表示闹铃歌曲编号。

## 9. 数码管扫描模块：`hex8_scan.sv`

这个模块把 32 位显示数据变成：

- 当前选通哪一位数码管；
- 当前这一位显示什么段码。

### 9.1 模块接口

```verilog
module hex8_scan (
    input  wire        clk,
    input  wire        reset_n,
    input  wire        en,
    input  wire [31:0] disp_data,

    output reg  [7:0]  sel,
    output reg  [6:0]  seg
);
```

- `disp_data`：8 个十六进制数字，每个 4 位。
- `sel`：位选，选中 8 位数码管中的某一位。
- `seg`：段选，决定这一位显示哪个数字。

### 9.2 扫描计数器

```verilog
localparam integer SCAN_CNT_MAX = 50_000;
reg [15:0] scan_cnt;
```

50 MHz / 50,000 = 1 kHz。

也就是每 1 ms 切换一次位选。8 位轮流扫一圈约 8 ms，人眼看起来就是同时亮。

计数器：

```verilog
always @(posedge clk or negedge reset_n) begin
    if (!reset_n) begin
        scan_cnt <= 16'd0;
    end else begin
        if (scan_cnt == SCAN_CNT_MAX - 1)
            scan_cnt <= 16'd0;
        else
            scan_cnt <= scan_cnt + 1'b1;
    end
end
```

### 9.3 位选循环

```verilog
reg [7:0] sel_r;

always @(posedge clk or negedge reset_n) begin
    if (!reset_n) begin
        sel_r <= 8'b0000_0001;
    end else if (scan_cnt == SCAN_CNT_MAX - 1) begin
        if (sel_r == 8'b1000_0000)
            sel_r <= 8'b0000_0001;
        else
            sel_r <= sel_r << 1;
    end
end
```

循环：

```text
0000_0001
0000_0010
0000_0100
...
1000_0000
0000_0001
```

### 9.4 根据当前位选取显示数据

```verilog
always @(*) begin
    case (sel_r)
        8'b0000_0001: data_tmp = disp_data[3:0];
        8'b0000_0010: data_tmp = disp_data[7:4];
        8'b0000_0100: data_tmp = disp_data[11:8];
        8'b0000_1000: data_tmp = disp_data[15:12];
        8'b0001_0000: data_tmp = disp_data[19:16];
        8'b0010_0000: data_tmp = disp_data[23:20];
        8'b0100_0000: data_tmp = disp_data[27:24];
        8'b1000_0000: data_tmp = disp_data[31:28];
        default:      data_tmp = 4'hF;
    endcase
end
```

当前选哪一位，就从 `disp_data` 中取对应 4 位。

### 9.5 七段译码

```verilog
always @(*) begin
    case (data_tmp)
        4'h0: seg = 7'b1000000;
        4'h1: seg = 7'b1111001;
        ...
        4'hE: seg = 7'b0111111;  // 横杠
        4'hF: seg = 7'b1111111;  // 空白
        default: seg = 7'b1111111;
    endcase
end
```

这是共阳极数码管，段码低电平点亮。所以：

- `0` 不是全 1，而是 `1000000`。
- `F` 是 `1111111`，表示全灭。
- `E` 被用作横杠，不是字母 E。

### 9.6 输出位选

```verilog
always @(*) begin
    if (en)
        sel = sel_r;
    else
        sel = 8'b0000_0000;
end
```

如果模块使能，就输出当前位选；否则所有位关闭。

## 10. 74HC595 驱动模块：`hc595_driver.sv`

74HC595 是串入并出的移位寄存器。FPGA 只用三根线：

- `ds`：串行数据；
- `sh_cp`：移位时钟；
- `st_cp`：锁存时钟。

就可以输出多位并行信号。

### 10.1 模块接口

```verilog
module hc595_driver (
    input  wire        clk,
    input  wire        reset_n,
    input  wire [15:0] data,
    input  wire        s_en,

    output reg         ds,
    output reg         sh_cp,
    output reg         st_cp
);
```

`data` 是要送给 74HC595 的 16 位数据。在顶层中：

```verilog
.data({1'b1, seg_seg, seg_sel})
```

这里拼成：

```text
1 位固定值 + 7 位段码 + 8 位位选 = 16 位
```

### 10.2 状态机

```verilog
localparam S_LOAD       = 3'd0;
localparam S_SHIFT_HIGH = 3'd1;
localparam S_SHIFT_LOW  = 3'd2;
localparam S_LATCH_HIGH = 3'd3;
localparam S_LATCH_LOW  = 3'd4;
```

状态含义：

| 状态 | 作用 |
|---|---|
| `S_LOAD` | 装载 16 位数据，准备发送第一位 |
| `S_SHIFT_HIGH` | 拉高移位时钟 |
| `S_SHIFT_LOW` | 拉低移位时钟，并准备下一位 |
| `S_LATCH_HIGH` | 拉高锁存时钟，把移位数据更新到输出 |
| `S_LATCH_LOW` | 拉低锁存时钟，回到装载状态 |

### 10.3 降低发送速度

```verilog
reg [1:0] div_cnt;
wire tick_en;
assign tick_en = (div_cnt == 2'd3);

always @(posedge clk or negedge reset_n) begin
    if (!reset_n)
        div_cnt <= 2'd0;
    else
        div_cnt <= div_cnt + 1'b1;
end
```

`tick_en` 每 4 个系统时钟出现一次。状态机只在 `tick_en` 为 1 时推进，避免 74HC595 时序太快。

### 10.4 发送流程

核心：

```verilog
S_LOAD: begin
    r_data  <= s_en ? data : 16'hFFFF;
    bit_cnt <= 5'd0;
    sh_cp   <= 1'b0;
    st_cp   <= 1'b0;
    ds      <= s_en ? data[15] : 1'b1;
    state   <= S_SHIFT_HIGH;
end
```

先保存数据，输出最高位 `data[15]`。

```verilog
S_SHIFT_HIGH: begin
    sh_cp <= 1'b1;
    state <= S_SHIFT_LOW;
end
```

移位时钟上升沿，74HC595 读入当前 `ds`。

```verilog
S_SHIFT_LOW: begin
    sh_cp <= 1'b0;

    if (bit_cnt == 5'd15) begin
        state <= S_LATCH_HIGH;
    end else begin
        bit_cnt <= bit_cnt + 1'b1;
        ds <= r_data[14 - bit_cnt];
        state <= S_SHIFT_HIGH;
    end
end
```

拉低时钟，准备下一位。发送完 16 位后进入锁存。

```verilog
S_LATCH_HIGH: begin
    st_cp <= 1'b1;
    state <= S_LATCH_LOW;
end

S_LATCH_LOW: begin
    st_cp <= 1'b0;
    state <= S_LOAD;
end
```

锁存时钟产生一个脉冲，74HC595 的并行输出更新。

## 11. 行为级歌曲 ROM：`song_rom.sv`

注意：工程实际在 `note_scheduler` 中例化的是 Vivado IP `anime_song_rom`，不是直接例化这个 `song_rom` 模块。不过 `song_rom.sv` 很适合理解音符怎么编码。

### 11.1 音符编码函数

```verilog
function automatic [15:0] N(
    input [3:0] octave,
    input [3:0] note,
    input [2:0] dur
);
    begin
        N = {octave, note, 2'd0, dur, 3'd0};
    end
endfunction
```

调用：

```verilog
N(4'd2, 4'd5, 3'd2)
```

表示：

- 高音区 `2`
- 音符 `5`
- 音长 `2`

### 11.2 休止符函数

```verilog
function automatic [15:0] R(
    input [2:0] dur
);
    begin
        R = {4'd0, 4'd0, 2'd0, dur, 3'd0};
    end
endfunction
```

休止符的音区和音名都是 0。`pitch_decoder` 遇到 note 不在 1 到 7 时输出 `counter_arr = 0`，于是 PWM 不发声。

### 11.3 地址到音符

```verilog
always @(*) begin
    case (addr)
        8'd0 : note_word = N(4'd2, 4'd5, 3'd2);
        8'd1 : note_word = N(4'd2, 4'd1, 3'd1);
        ...
        default: note_word = R(3'd4);
    endcase
end
```

这就是“乐谱”。地址每增加 1，就进入下一个音符。

实际工程里把类似数据生成到了 `.coe` 文件，再由 Block Memory Generator 生成 ROM IP。

## 12. 约束文件：`anime_music_player.xdc`

Verilog 只描述逻辑，不知道你的 `key0` 到底接板子哪个引脚。XDC 文件负责把逻辑端口绑定到 FPGA 物理引脚。

### 12.1 时钟约束

```tcl
set_property -dict {PACKAGE_PIN U18 IOSTANDARD LVCMOS33} [get_ports clk]
create_clock -period 20.000 -name clk [get_ports clk]
```

第一行：`clk` 接 FPGA 的 U18 引脚。

第二行：告诉 Vivado，这个时钟周期是 20 ns，也就是 50 MHz。没有这个约束，Vivado 不知道要按多快来做时序优化。

### 12.2 复位和蜂鸣器

```tcl
set_property -dict {PACKAGE_PIN H18 IOSTANDARD LVCMOS33} [get_ports reset_n]
set_property -dict {PACKAGE_PIN G15 IOSTANDARD LVCMOS33} [get_ports beep]
```

`LVCMOS33` 表示 3.3 V CMOS 电平标准。

### 12.3 按键

```tcl
set_property -dict {PACKAGE_PIN H20 IOSTANDARD LVCMOS33} [get_ports key0]
set_property -dict {PACKAGE_PIN H16 IOSTANDARD LVCMOS33} [get_ports key1]
set_property -dict {PACKAGE_PIN J20 IOSTANDARD LVCMOS33} [get_ports key2]
set_property -dict {PACKAGE_PIN J19 IOSTANDARD LVCMOS33} [get_ports key3]
```

这四个就是 EDA 拓展板的 S0 到 S3。

### 12.4 LED

```tcl
set_property -dict {PACKAGE_PIN G17 IOSTANDARD LVCMOS33} [get_ports {led[0]}]
...
set_property -dict {PACKAGE_PIN K18 IOSTANDARD LVCMOS33} [get_ports {led[7]}]
```

每个 LED 位都要绑定一个物理引脚。

### 12.5 数码管 74HC595

```tcl
set_property -dict {PACKAGE_PIN D20 IOSTANDARD LVCMOS33} [get_ports seg_dio]
set_property -dict {PACKAGE_PIN E19 IOSTANDARD LVCMOS33} [get_ports seg_sclk]
set_property -dict {PACKAGE_PIN F17 IOSTANDARD LVCMOS33} [get_ports seg_rclk]
```

这三根线分别是串行数据、移位时钟、锁存时钟。

### 12.6 拨码开关

```tcl
set_property -dict {PACKAGE_PIN K14 IOSTANDARD LVCMOS33} [get_ports {sw_vol[0]}]
set_property -dict {PACKAGE_PIN L15 IOSTANDARD LVCMOS33} [get_ports {sw_vol[1]}]
set_property -dict {PACKAGE_PIN E17 IOSTANDARD LVCMOS33} [get_ports sw_mode]
```

音量用两位，模式开关用一位。

闹铃相关：

```tcl
set_property -dict {PACKAGE_PIN G14 IOSTANDARD LVCMOS33} [get_ports {sw_alarm_song[0]}]
set_property -dict {PACKAGE_PIN J14 IOSTANDARD LVCMOS33} [get_ports {sw_alarm_song[1]}]
set_property -dict {PACKAGE_PIN H15 IOSTANDARD LVCMOS33} [get_ports sw_alarm_en]
set_property -dict {PACKAGE_PIN D18 IOSTANDARD LVCMOS33} [get_ports sw_alarm_set]
```

## 13. 从开机到发声：完整运行过程

假设板子刚复位，且 `sw_mode=0` 音乐模式。

### 13.1 复位后

顶层：

```text
play_en = 0
song_id = 0
speed_level = 1
```

时钟核心：

```text
当前时间 = 00:00:00
默认闹铃 = 00:01
clock_running = 1
alarm_active = 0
```

蜂鸣器不会响，因为 `play_en=0`。

### 13.2 按 S0 开始播放

1. `key0` 物理按下。
2. `key_debounce` 等电平稳定 20 ms。
3. 输出 `key0_pulse = 1` 一个时钟周期。
4. 顶层音乐控制逻辑执行：

   ```verilog
   play_en <= ~play_en;
   ```

5. `play_en` 从 0 变 1。

### 13.3 播放模块开始工作

1. `effective_play_en = 1`。
2. `note_scheduler` 开始计时。
3. ROM 根据地址输出当前音符 `note_word`。
4. `pitch_decoder` 把 `note_word` 转成 `counter_arr`。
5. 顶层根据 `sw_vol` 产生 `counter_ccr`。
6. `pwm_gen` 输出 PWM 到 `beep`。
7. 蜂鸣器发声。

### 13.4 音符切换

1. `note_scheduler` 的 `tick_cnt` 数到 `note_ticks`。
2. 地址 `addr` 加 1。
3. `note_change = 1` 一个时钟周期。
4. 节奏 LED 循环移位。
5. ROM 输出下一音符。
6. 蜂鸣器频率变化，听起来就是下一音。

### 13.5 按 S1 切歌

1. `key1_pulse = 1`。
2. 顶层更新 `song_id`。
3. `note_scheduler` 发现：

   ```verilog
   song_id != last_song_id
   ```

4. 地址跳到新歌曲 `start_addr`。
5. 新歌曲从头开始播放。

## 14. 从时钟到闹铃响：完整运行过程

假设 `sw_mode=1` 进入时钟模式。

### 14.1 进入时钟模式

`clock_mode_rise = 1`，顶层关闭普通音乐：

```verilog
play_en <= 1'b0;
```

数码管显示切换为：

```verilog
disp_data = clock_disp_data;
```

LED 也切换为时钟模式显示。

### 14.2 时钟自动走

`clock_core` 内部：

1. `div_cnt` 每个时钟加一。
2. 数到 50,000,000 个周期产生 `tick_1s`。
3. 秒个位加一。
4. 满 9 进位。

### 14.3 设置时间

在时钟模式、`alarm_set_mode=0`：

- S0：选择小时、分钟、秒。
- S1：当前字段加一。
- S2：当前字段减一。
- S3：暂停/继续。

### 14.4 设置闹铃

在时钟模式、`alarm_set_mode=1`：

- S0：选择闹铃小时或闹铃分钟。
- S1：加一。
- S2：减一。
- `sw_alarm_song`：选择闹铃歌曲。
- `sw_alarm_en`：打开闹铃。

数码管显示：

```text
A#-HH-MM
```

### 14.5 闹铃触发

当当前时间匹配闹铃时间，并且秒为 00：

```verilog
alarm_active <= 1'b1;
```

顶层看到：

```verilog
clock_mode && clock_alarm_active
```

于是：

```verilog
effective_play_en = 1
effective_song_id = alarm_song_id
effective_speed_level = 1
```

音乐播放链路被强制启动，蜂鸣器播放闹铃歌曲。

### 14.6 闹铃停止

两种停止方式：

1. 自动 10 秒停止。
2. 按 S3 停止。

## 17. 初学者最容易卡住的点

### 17.1 为什么有些地方用 `assign`，有些地方用 `always`

简单规则：

- 一根线由简单逻辑直接连出来，用 `assign`。
- 复杂组合逻辑，用 `always @(*)`。
- 需要记住过去状态，用 `always @(posedge clk ...)`。

### 17.2 为什么按键不是直接用

因为按键会抖动，而且是异步输入。直接用会出现：

- 一次按下触发多次；
- 状态异常跳变；
- 偶发不稳定。

所以必须同步和消抖。

### 17.3 为什么数码管要扫描

因为实际硬件通常不会给每一位数码管一套完整独立段码，而是共用段线，轮流选通每一位。

扫描速度足够快，人眼看起来就是 8 位同时亮。

### 17.4 为什么蜂鸣器要 PWM

无源蜂鸣器不会自己发固定音调，需要外部给方波。方波频率决定音高，占空比影响响度。

### 17.5 为什么音乐和闹铃共用一套播放链路

因为它们本质都是“播放某首歌”。闹铃只是改变播放使能和歌曲编号，不需要再写一个蜂鸣器模块。

## 18. 如果你要自己复现，建议顺序

不要一上来就写顶层。建议按这个顺序理解和实现：

1. 先写 `pwm_gen`，让蜂鸣器发固定频率。
2. 再写 `pitch_decoder`，让不同数字对应不同音高。
3. 再写一个简单 ROM，让地址对应音符。
4. 再写 `note_scheduler`，让地址按时间自动加。
5. 再写 `key_debounce`，让按键可靠控制播放。
6. 再写 `hex8_scan`，让数码管能显示数字。
7. 再写 `hc595_driver`，把数码管数据送出去。
8. 再写 `clock_core`，实现电子钟和闹铃。
9. 最后写 `anime_music_player_top`，把所有模块连起来。

这个顺序比直接读顶层容易很多。

## 19. 一句话总结整个工程

这个系统的本质是：用 50 MHz 时钟驱动一堆计数器和状态寄存器；按键消抖后改变状态；音乐模块把歌曲地址变成音符，再把音符变成 PWM 方波；时钟模块把 50 MHz 分频成 1 秒并维护 BCD 时间；顶层根据模式选择最终显示和播放内容。
